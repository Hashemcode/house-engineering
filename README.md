# Advanced Engineering House — company website

Bilingual (English / Arabic) website for **Advanced Engineering House Co.** — an MEP, fire-protection
and network engineering contractor based in Dammam, Saudi Arabia, with a branch in Dubai.

| | |
|---|---|
| **Live site** | https://www.house-engineering.com |
| **Arabic** | https://www.house-engineering.com/ar/ |
| **Admin panel** | https://www.house-engineering.com/admin/ |
| **Preview (same build)** | https://hashemcode.github.io/house-engineering/ |
| **Repository** | `Hashemcode/house-engineering` (branch `main`) |
| **Running cost** | $0 — GitHub Pages + Cloudflare Workers free tiers |

The site is a **static site generated by a Python script**. Staff edit content through the admin
panel; every save commits to this repository, which triggers a rebuild and redeploy (~1 minute).

---

## 1. How it fits together

```
          staff edit                     git push
  /admin ───────────► Cloudflare Worker ──────────► GitHub repo
  (browser)            (aeh-admin-api)                  │
                                                        │ GitHub Actions
                                                        ▼
                                              python build.py → dist/
                                                        │
                                                        ▼
                                               GitHub Pages (live site)
```

- **Content** lives in `content/*.json` (bilingual values, `{"en": "...", "ar": "..."}`).
- **Templates and page structure** live in `build.py`.
- **Build output** goes to `dist/` (git-ignored; produced fresh on every deploy).

## 3. Local development

```bash
python3 build.py                 # writes dist/  (standard library only, no dependencies)
python3 -m http.server 8765 -d dist
# http://localhost:8765  ·  http://localhost:8765/ar/
```

**Important:** staff edits commit directly to `main`, so always pull before pushing:

```bash
git pull --rebase origin main
```

Pushing to `main` is all that is needed to deploy — the GitHub Action builds and publishes.

## 4. Content model

Every text field is an object with English and Arabic. If Arabic is empty, English is shown.

```jsonc
// content/projects.json — one entry
{
  "id": "quarter-hotel",
  "name":     { "en": "Quarter Hotel", "ar": "فندق كوارتر" },
  "client":   { "en": "Quarter Hotel", "ar": "فندق كوارتر" },
  "location": { "en": "", "ar": "" },
  "image": "p-quarter-hotel.webp",      // relative to src/assets/img/ ; "" = table row
  "categories": ["hvac", "fire", "electrical", "plumbing", "security"],
  "tags":  [{ "en": "HVAC", "ar": "التكييف" }],
  "scope": [{ "en": "Electrical, HVAC and plumbing systems", "ar": "أنظمة الكهرباء والتكييف والسباكة" }],
  "featured": true                       // show in the home page slider
}
```

Valid `categories` (they drive the Projects filter buttons) are defined in `build.py` → `CATS`:
`hvac`, `fire`, `electrical`, `plumbing`, `security`.

Home page statistics are **computed**, not typed: projects = number of entries, disciplines =
number of services, partners = number of logos.

Text coming from `content/*.json` is HTML-escaped at build time, so staff cannot break the page
layout (or inject markup) by typing special characters.

### Adding an editable field

1. Add it to the relevant `content/*.json` entries.
2. Render it in `build.py`.
3. Add it to the matching schema in `src/admin/admin.js` (`COLL` or `SETTINGS_FIELDS`) plus labels
   in that file's `T` dictionary (both `en` and `ar`).

## 5. Admin panel

`/admin/` — staff sign in with email + password. Sections: **Projects, Services, Partners,
Company info, Admins** (owners only) and **My account**.

- Side-by-side English/Arabic inputs on every field; the interface itself toggles to Arabic (RTL).
- Photo uploads are resized in the browser (max 1800px, WebP) before being committed to
  `src/assets/img/uploads/`.
- Items can be reordered, and projects toggled on/off the home page.
- After **Save & publish** a badge shows "Publishing…", then "Website is up to date" (~1 minute).
- Every change is an ordinary git commit — full history, and anything deleted can be restored.

Non-technical staff guide: [`ADMIN-GUIDE.md`](ADMIN-GUIDE.md).

## 6. Admin API (Cloudflare Worker)

Worker **`aeh-admin-api`** → `https://aeh-admin-api.house-engineering.workers.dev`

| Route | Purpose |
|---|---|
| `POST /api/login` | email + password → signed session token (12 h) |
| `GET /api/me` | current user |
| `GET /api/content` | all four content files with their git SHAs |
| `PUT /api/content/:file` | commit a content file (`settings`/`services`/`projects`/`partners`) |
| `POST /api/upload` | commit an image to `src/assets/img/uploads/` |
| `GET /api/deploy` | status of the latest GitHub Actions run |
| `POST /api/password` | change own password |
| `GET/POST /api/users`, `DELETE /api/users/:email` | manage admins (owner only) |

**Storage:** Cloudflare KV namespace bound as `USERS`, one record per user at `user:<email>`
(`{ email, name, role, hash }`), passwords hashed with PBKDF2-SHA256 (100k iterations, random salt).
Failed logins are rate-limited (8 attempts per 15 minutes).

**Secrets** (set with `wrangler secret put`, never stored in the repo):

- `GITHUB_TOKEN` — fine-grained PAT limited to this repository (Contents: read/write, Actions: read)
- `SESSION_SECRET` — random string used to sign session tokens

**Deploying worker changes:**

```bash
cd admin-api
npx wrangler deploy
```

**Creating an admin from the CLI** (normally done in the panel's *Admins* tab):

```bash
cd admin-api
PW='choose-a-password'
VAL=$(python3 -c "
import os,hashlib,base64,json,sys
pw=sys.argv[1]; salt=os.urandom(16)
h=hashlib.pbkdf2_hmac('sha256',pw.encode(),salt,100000,32)
print(json.dumps({'email':'person@example.com','name':'Name','role':'editor',
  'hash':f'pbkdf2\$100000\${base64.b64encode(salt).decode()}\${base64.b64encode(h).decode()}'}))" "$PW")
npx wrangler kv key put "user:person@example.com" "$VAL" --binding USERS --remote
```

Roles: `editor` (content only) and `owner` (content + manage admins).

| CNAME | www | hashemcode.github.io | the live site |
| MX | @ | houseengineering-com01c.mail.protection.outlook.com | **email — do not touch** |
| TXT | @ | `v=spf1 include:secureserver.net -all` | **email SPF — do not touch** |
| TXT | @ | `NETORGFT…onmicrosoft.com` | **Microsoft 365 verification — do not touch** |
| CNAME | autodiscover, email, lyncdiscover, msoid, sip | Microsoft / GoDaddy hosts | **email & Teams — do not touch** |
| SRV | `_sip._tls`, `_sipfederationtls._tcp` | Lync/Teams | **do not touch** |

Email runs on Microsoft 365, completely separate from the website. **Never modify the MX, TXT, SRV
or Microsoft CNAME records.** Note that every DNS change in GoDaddy requires an SMS verification
code sent to the company phone.

The repository's `CNAME` file (written by `build.py` into `dist/`) and the Pages custom-domain
setting must both stay `www.house-engineering.com`.

## 8. Contact form

The form posts to **FormSubmit** (`formsubmit.co`), delivering to `info@house-engineering.com` with
`suleiman@house-engineering.com` in copy; if the request fails it falls back to opening the
visitor's email client. FormSubmit requires a **one-time activation link**, emailed to `info@` the
first time the form is submitted. Until someone clicks it, submissions fall back to the mail client.

## 9. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Admin says "Someone else saved changes at the same time" | Two people saved at once. Reload the page and redo the edit. |
| Admin shows "Publishing failed" | Check the Actions tab of the repo for the failed run. |
| `git push` rejected | Staff edits landed first — `git pull --rebase origin main`, then push. |
| Browser still shows the old site | Local DNS cache: `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder` |
| Uploaded photo not visible yet | It appears after the rebuild finishes (~1 minute). |
| Admin panel says "not connected" | `src/admin/config.js` lost the Worker URL. |
